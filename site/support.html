About

Something isn't working

Most problems show up in two places, the sync log in the app and one command on your computer, so look there first. Below are short answers to the common problems. If none of them fits, write to support@healthaccessmcp.com.

Check the app

  • Settings → Trust → Sync log lists every time the app woke and what it wrote. If a session is missing, you can see here whether the app ran and what it found. The small buttons at the bottom write the most recent days again.
  • Settings → Trust → What left this phone lists every event the app sent in this session, with the host it went to. With usage statistics off, it says nothing left.
  • Settings → About shows the app version and the build number in brackets.

Check the computer

npx -y -p healthaccess-mcp healthaccess doctor   # checks the folder: directories, index, every file, schema versions
npx -y healthaccess-mcp --check                  # prints the folder the server uses and whether usage statistics are on
npx -y healthaccess-mcp --version                # prints the server version

Add --dir "<path to the folder>" to any of them to point them at a folder. If you installed with cargo, leave out the npx part: healthaccess doctor, healthaccess-mcp --check, healthaccess-mcp --version. doctor ends with healthy when everything in the folder reads correctly, or with PROBLEMS FOUND and the reasons when it doesn't.

Common problems

Google Drive or OneDrive is greyed out in the folder picker

You haven't missed a step. When an app asks for a folder, iOS only offers storage apps that let other apps open their folders. iCloud Drive, On My iPhone and network drives do. Google Drive and OneDrive don't, so they show up greyed out for every app that asks for a folder, not only this one. Signing in again, switching them on in the Files app or restarting the phone doesn't change it. From app version 1.1.0, use Settings → Cloud upload instead: Health Access uploads your files to Google Drive itself, into a new folder called Health Access at the top level of your Drive. How it works. OneDrive is planned; you can ask for it in the same place. Until then, pick a folder in iCloud Drive. It syncs to a Mac on its own and to a PC with iCloud for Windows.

The app says "Not connected yet"

Your AI client hasn't started the MCP server yet. Clients start it when a new chat or session begins, so start one. The server then writes a small file into mcp/clients/ in your folder. Once your folder provider has synced that file to the phone, the app shows the connection. The app checks again every time you bring it to the front, so switch to it after a minute. It also goes back to "Not connected yet" if your AI hasn't used the server for 7 days.

No new sessions in the folder

Open the app once after the workout. The iPhone has to be unlocked, because Apple Health data can't be read while the phone is locked, so the app writes the files the next time you unlock it. Then your folder provider has to sync the files to your computer. On a Mac, iCloud Drive shows a cloud icon on files that aren't downloaded yet. If the sync log shows a run with nothing new, check that Health Access is allowed to read your workouts in Health → Sharing → Apps → Health Access.

Plans don't reach the Watch

Your AI writes the plan into the folder. It reaches the Watch when you open the app, tap Put on Watch on that plan and confirm, or on its own if you switched on "Put new plans on my Watch automatically" in the Import tab. Either way the plan file has to have synced to the phone first. Putting a workout on the Watch uses Apple's WorkoutKit and needs an Apple Watch paired with this iPhone. Settings → Watch sets what Put on Watch does: schedule the session, or open Apple's preview sheet. The preview sheet doesn't report back, so the app marks those plans as unconfirmed.

The MCP server can't find the folder

Without --dir, the server looks for the folder in iCloud Drive, then in the other file providers, then in ~/Documents. From 1.0.4 it also starts without a folder. Your AI is then told there's nothing to read yet, and the server looks again on every call. If it doesn't find one, or picks the wrong one, tell it where the folder is with --dir "<path to the folder>" in the arguments your AI client uses to start the server. On a Mac, a folder in iCloud Drive is at ~/Library/Mobile Documents/com~apple~CloudDocs/<folder name>. Dropbox, Google Drive and OneDrive folders usually live under ~/Library/CloudStorage/. For example:

{
  "mcpServers": {
    "healthaccess": {
      "command": "npx",
      "args": ["-y", "healthaccess-mcp", "--dir", "/Users/<you>/Library/Mobile Documents/com~apple~CloudDocs/Health Access"]
    }
  }
}

Then start a new session in the client. npx -y healthaccess-mcp --check prints the folder the server uses and any other Health Access folders it found. Add --dir "<path>" to it to test a path. The pages under Connect an AI show where each client keeps these settings.

Write to me

Write to support@healthaccessmcp.com and include:

  • your iOS version;
  • the app version and build, from Settings → About;
  • which AI client you use, with its version if you know it;
  • what you expected, and what happened instead;
  • the output of npx -y -p healthaccess-mcp healthaccess doctor.

Please don't send me health data files from your folder. I don't need them to help you. The doctor output holds no health values, but it shows your folder's path and your computer's name and, where something failed, file names and Health data types. Remove anything you'd rather not share. How your mail is handled is in the privacy policy.

Purchases

The support card and the coffee are sold by Apple, so refunds go through Apple at reportaproblem.apple.com. I can't see who bought anything and can't refund a purchase myself. On a new phone or after a reinstall, Settings → About → Restore purchases brings back a removed support card.

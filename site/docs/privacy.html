About

Where does my data go?

Into the folder you picked. From app version 1.1.0, it also goes to a drive you connect, if you switch on Cloud upload. There's no server of mine to send it to and no account to tie it to. The app has a screen called "What left this phone". It stays empty unless you turn usage statistics on, use Cloud upload or ask for a planned drive (OneDrive or Box). Usage statistics send only the events listed below, and they never contain a health value.

What it doesn't have

  • There's no server. None of my code runs anywhere except on your phone and your computer. The MCP server is a program on your Mac that reads a folder, and it doesn't listen for any connections.
  • There's no account. You don't sign up for anything, so there's no account data that could leak, be sold or get lost.
  • It can't write to Apple Health. The app only asks to read, and only the types you tick. Plans go to the Watch through WorkoutKit, which is a separate permission and doesn't touch your health records.
  • Usage statistics are off by default. They stay off until you turn them on in Settings. No SDK in the app is configured to track you, and there's no advertising identifier and no crash reporting that carries data.

What leaves the phone

1. Your files, to your own storage

The folder you picked syncs through your storage provider, for example iCloud Drive or your NAS. It goes through your own account with them, under their terms. Your photos and documents already go to the same place. If you pick "On My iPhone", nothing leaves the phone at all, but then your AI on the computer can't reach the folder either. The files are plain JSON, so encrypt the folder if your provider offers it.

From app version 1.1.0, you can switch on Cloud upload (Settings → Cloud upload). Then the app uploads the folder itself to Google Drive, a WebDAV server or S3 storage that you connect. The upload goes from your iPhone straight to your drive, and nothing passes through a server of mine. On Google Drive, the app can reach only the files it created. How Cloud upload works.

The MCP server on your computer writes one small file into the same folder, mcp/clients/<id>.json. It holds the client's name and version, your computer's name, a call count and the name of the last tool. With it, the app can show that an AI is connected. It never contains tool arguments or results.

2. Usage statistics, only if you turn them on

They're off by default. When they're on, the app sends these events from the phone to PostHog, an analytics service:

EventProperties
app_openednone
export_completedworkout_count, duration_ms, trigger (observer, background task, foreground or manual)
export_failederror_domain, code
plan_schedulednone
plan_put_on_watchmethod (schedule, auto or preview)
setup_message_copiednone
ai_connectedclient (claude-code, claude-desktop, cursor, codex, lm-studio, goose or other), once per AI client. It never includes the computer's name, the file name or a version.

Each event also carries the app version and build, the OS name and version, the device type (iPhone), the analytics SDK's name and version, and a random id. The app creates that id at install, and it is neither your Apple ID nor your name. An allowlist (a fixed list of what may pass) strips everything else the SDK would normally attach (locale, time zone, network, screen size). No event ever contains a health value, a file name or a folder path. The event helpers in the code only accept numbers and fixed words, so a health value can't get in by accident.

From app version 1.1.0, one event doesn't depend on that switch. If you tap OneDrive or Box in Settings → Cloud upload to ask for it, and you confirm, the app sends one anonymous drive_interest event. It doesn't turn usage statistics on.

3. The MCP server's own statistics, only if you turn them on

The server you get with npx -y healthaccess-mcp has none. None of the binaries (the ready-built programs) I publish can send statistics. I build the ones on npm and in the release archives without the HTTP client, and the npm binaries contain no network code at all. Only a build you make yourself from source with the default features can send them. Even then, it stays off unless you set both telemetry = true and a PostHog key in ~/.config/healthaccess/config.toml (or pass --telemetry). When it's on, two events go from your computer to the PostHog host you configured:

EventProperties
mcp_startedversion
mcp_tool_calledtool, duration_ms, ok, and on failure error_kind, one of io, json, schema, not_found, ambiguous, validation, refused, codec, config

The events also carry the server's name and version, the OS name, and an anonymous random id. The server writes that id to the config file on first use. The events never contain tool arguments, results, workout contents, file names or paths. If you build from source and want no network code in it either, use cargo install --path mcp --no-default-features.

4. Whatever you ask your AI to read

This one is up to you, and it's the biggest one. When you ask Claude, ChatGPT or Cursor about your swim, the AI reads the session data. That data becomes part of the conversation and goes to that company's servers under their terms. This part depends on the AI you picked, not on this app. If you want the data to stay on your Mac, use a local model. The MCP works the same either way.

Where to check

  • In the app: Settings, Privacy, "What left this phone", and the sync log, which lists every background wake and what it wrote.
  • On the computer: npx -y healthaccess-mcp --check prints the telemetry state (telemetry is the usage statistics). The event lists above are in Telemetry.swift and mcp/src/telemetry.rs. The source is public on GitHub.
  • This site doesn't set cookies or run analytics, and it loads nothing from anyone but its own host. Even the typefaces come from here.
  • The formal version of all this, with the legal bases and your rights, is the privacy policy.

Apple's part

Apple keeps Health data encrypted while the phone is locked, so the app can only export after you unlock the phone. The app's privacy manifest declares that it does no tracking, and the app has no entitlement (a permission from Apple) to write to Health. Health records never go to iCloud through this app. Only the files you asked it to write go to the folder you picked.

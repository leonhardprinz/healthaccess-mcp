Connect an AI

Apple Health with local models

Any MCP host that can launch a program on your computer works. You give it the command npx -y healthaccess-mcp. A plain model runner like Ollama has no MCP host built in, so there you use the files or the command line instead. With a local model, nothing leaves your Mac.

The command every host needs

npx -y healthaccess-mcp

It runs over stdio and needs no environment variables. The server finds your Health Access folder on its own (iCloud Drive, then the other file providers, then ~/Documents). To pick it yourself, add --dir "/absolute/path". You need Node.js 18 or newer for npx, and a GUI app that doesn't see your shell's PATH needs the full path from which npx. To build from source instead, run cargo install --path mcp --locked in the repository.

LM Studio

LM Studio can host MCP servers since version 0.3.17 and uses the same mcp.json format as Cursor. In the right sidebar, open the Program tab, then Install, then Edit mcp.json, and add:

{
  "mcpServers": {
    "healthaccess": {
      "command": "npx",
      "args": ["-y", "healthaccess-mcp"]
    }
  }
}

Pick a model that's good at tool calls. Small models often call list_workouts fine and then struggle with the longer get_workout result. Ask for one session at a time and leave the heart-rate series out (it's off by default).

Goose

Goose, Block's open-source agent, adds stdio servers as extensions. To do it interactively, run goose configure, choose Add Extension, then Command-line Extension, and paste the command above when it asks. Or edit ~/.config/goose/config.yaml: to confirm

extensions:
  healthaccess:
    name: Health Access
    type: stdio
    cmd: npx
    args:
      - -y
      - healthaccess-mcp
    enabled: true
    timeout: 300

Codex CLI

OpenAI's Codex CLI starts stdio servers itself. This command registers the server for every project:

codex mcp add healthaccess -- npx -y healthaccess-mcp

Or edit ~/.codex/config.toml (or .codex/config.toml in a trusted project, to use it in that project only):

[mcp_servers.healthaccess]
command = "npx"
args = ["-y", "healthaccess-mcp"]
startup_timeout_sec = 60

By default Codex gives a server 10 seconds to start. The first start downloads the server from npm, so 60 gives it enough time, and later starts take well under a second. To check, run codex mcp list, or /mcp inside a Codex session. Codex uses OpenAI's cloud models unless you point it at a local one, so whatever it reads from the folder goes to that model's provider.

Any other MCP host

If the host has a config file with mcpServers, copy the Claude Desktop snippet. If it asks for a command and arguments, the command is npx and the arguments are -y and healthaccess-mcp. The server identifies itself as healthaccess-mcp and lists thirteen tools.

Ollama and other plain model runners, without MCP

Your training data is all in plain files, so any model that can read text can read it. There are two ways:

  1. The briefing. briefing.md, one page the app writes after every sync, fits any context window.
  2. The command line. healthaccess prints the same views the MCP serves, as tables or as JSON with --json. It's in the same npm package (npm install -g healthaccess-mcp puts both on your PATH). Pipe the output into the model: 
    healthaccess summary --weeks 4 --json \
  | ollama run llama3.2 "This is my swimming and rowing training summary by week. In five sentences, what changed over the four weeks, and what would you ask me before suggesting anything?"

healthaccess show 7A1C3E90 --json \
  | ollama run llama3.2 "Explain this swim session to me in plain words: the parts, where the heart rate went, anything odd."

You can get a plan back to the Watch without the MCP too. Have the model write the plan JSON, then run healthaccess plan push session.json, which validates it and puts it into plans/. The app shows "Put on Watch" within a minute.

A first prompt to try

List my last 5 workouts, one line each. Pick the one you would most want to know more about and tell me why, in two sentences. Then ask me how it felt.

Connect an AI

Apple Health in Claude Code

You register the server with one command. After that, Claude Code can list your Apple Watch workouts, open a session with every interval and its heart rate, read your vitals and write a plan that goes onto your Watch.

Before you start

  1. The Health Access app on your iPhone has already written files into your folder, and that folder syncs to this computer (iCloud Drive, for example).
  2. You have Node.js 18 or newer, so npx is there. To check, run npx --version. If it's missing, install Node from nodejs.org or with brew install node.

Register the server

claude mcp add --scope user healthaccess -- npx -y healthaccess-mcp
  • There's nothing else to set up. The first start downloads the server for your computer from npm (a few MB), and later starts use the copy npm keeps.
  • You don't need to give it a path. The server looks for your Health Access folder in iCloud Drive, then in Dropbox, Google Drive, OneDrive and Box, then in ~/Documents, and uses the one the app updated last.
  • To pick the folder yourself, add it at the end: npx -y healthaccess-mcp --dir "/path/to/your/folder". iCloud Drive folders are under ~/Library/Mobile Documents/com~apple~CloudDocs/, the other providers are under ~/Library/CloudStorage/.
  • --scope user makes the server available in every project. Without it, the server is only registered for the current project.

If you'd rather check it into a repository, put the same thing in a project file, .mcp.json in the project root:

{
  "mcpServers": {
    "healthaccess": {
      "command": "npx",
      "args": ["-y", "healthaccess-mcp"]
    }
  }
}

Or install it as a plugin

This gives you the same server plus the eleven prompts as skills, in two commands. Use either the plugin or the command above, not both, or Claude starts the server twice.

claude plugin marketplace add leonhardprinz/healthaccess-mcp
claude plugin install healthaccess-mcp@healthaccess

Check that it works

claude mcp list                         # healthaccess should show as connected
npx -y healthaccess-mcp --check         # prints the folder it found and where from

Inside a Claude Code session, /mcp lists the server and its thirteen tools: list_workouts, get_workout, get_vitals, training_summary, rate_workout, push_plan, get_plan_status, list_plans, get_day, get_days, get_catalog, get_profile, list_ecgs. The Health Access app shows "Connected" once a session has started the server.

A first prompt to try

List my last 5 workouts, one line each. Then open the newest one and tell me in plain words what the parts were and where the heart rate went. Before you judge it, ask me how it felt.

For more ideas, see the prompts. Each one has the AI ask you first, then read the data, then write.

If something doesn't work

  • "Health Access has no folder to read on this computer yet" (before 1.0.4: "no Health Access folder found", and the server did not start): the folder hasn't synced to this computer yet, or it's somewhere the search doesn't look. Open it in Finder so it downloads, or pass it with --dir. The server looks again on every call, so you don't need to restart anything once the folder is there.
  • Two folders found: the server won't pick one, because one of them could be a folder someone shared with you. It lists both and stops. Pass --dir with yours, or put dir = "…" into ~/.config/healthaccess/config.toml.
  • A workout is missing in list_workouts but the file exists: the app's index.json is behind. The server also finds ids by scanning workouts/, so get_workout still works with the file name or the 8-character id from it.
  • Logs go to stderr. HEALTHACCESS_LOG=debug gives you more detail. Claude Code shows server stderr under /mcp.
  • Folder and zone bounds can also be set once in ~/.config/healthaccess/config.toml. If you also pass --dir, that wins.
  • From source instead of npm: install stable Rust, run cargo install --path mcp --locked in the repository, and register healthaccess-mcp instead of npx -y healthaccess-mcp.
